調べ物をした直後は内容を覚えていても、数日後に見返すと「このページを何のために保存したんだっけ」となることがあります。リンクだけを残しても、当時の疑問や重要だと思った箇所までは保存されないからです。

あとから使えるメモにするには、情報をたくさん写すより、**何を確かめ、どこを根拠にし、次に何をするのか**を短く残す方が役立ちます。

![問いから次の行動までをつなぐメモの流れ](/images/research-note-flow.svg)

## 1. 最初に「調べた理由」を一行で書く

メモの先頭には、調べ始めたときの疑問を残します。

たとえば「このサービスの料金はいくらか」だけだと、あとで見返したときに比較したいのか、契約を検討しているのかが分かりません。

- 悪い例：サービスAについて
- よい例：サービスAの無料プランで、ファイルを何個まで保存できるか確認する

疑問を具体的にすると、必要な情報と不要な情報を分けやすくなります。

## 2. 公式ページを根拠として残す

検索結果の短い説明や、誰かのまとめ記事だけで結論を決めないようにします。仕様・料金・利用条件などは、運営元の公式ページや公式ヘルプを先に確認します。

メモにはURLだけでなく、次の情報も残します。

| 項目 | 記録すること |
|---|---|
| ページ名 | どの公式ページを見たか |
| 該当箇所 | 見出し名や設定項目 |
| 確認日 | いつ確認したか |
| 条件 | 対象プラン、OS、地域、バージョンなど |
| 未確認点 | ページを読んでも分からなかったこと |

特に料金や機能は変更されることがあります。確認日があれば、古いメモをそのまま現在の情報として使う危険を減らせます。

## 3. 事実・自分の判断・未確認を分ける

メモの中で、公式ページに書かれていた事実と、自分がそこから考えたことを混ぜないようにします。

- **確認できた事実**：公式ページには、保存容量の上限が記載されている。
- **自分の判断**：自分の用途なら、その上限で足りそうだ。
- **未確認**：容量を超えたときに、既存ファイルがどう扱われるかは分からない。

この3つを分けておくと、後日読み返したときに「公式に確認したこと」と「そのときの予想」を区別できます。

## 4. 最後に次の行動を書く

メモの最後は、調べた内容の要約だけで終わらせず、次にすることを一つ書きます。

- 実際に無料プランを試す
- 公式ヘルプの別ページで保存上限を確認する
- 他の候補と料金を比較する
- 今回は採用しない理由を記録する

次の行動が決まっていないなら「追加確認なし。現時点では保留」と書いておくだけでも十分です。

## そのまま使えるメモの型

以下の項目をコピーして、調べ物ごとに使えます。

| 項目 | 記入欄 |
|---|---|
| 疑問 | 何を確かめたいか |
| 結論 | 現時点で分かったこと |
| 根拠 | 公式ページのURL・見出し |
| 確認日 | YYYY-MM-DD |
| 条件 | バージョン・プラン・対象など |
| 未確認 | まだ判断できないこと |
| 次の行動 | 試す・比較する・保留する |

## メモを更新するときの注意

新しい情報が見つかったら、古い記録を何も残さず書き換えるのではなく、確認日と変更点を追記します。仕様が変わったのか、自分の理解が変わったのかを後から追えるようにするためです。

メモは保存すること自体が目的ではありません。次に同じ疑問が出たとき、前回の調査を最初からやり直さずに済むことが大切です。
